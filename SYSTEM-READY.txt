WHAT WAS FIXED:
═══════════════════════════════════════════════════════════════════════════════

1. TMux Access from Windows ✅
   Problem: "'tmux' is not recognized as an internal or external command"

   Root Cause:
   - conductor-spawn.js was calling tmux directly from Windows
   - tmux is a Linux utility, only available in WSL

   Solution Applied:
   - Updated ALL tmux commands to use WSL wrapper pattern
   - Pattern: wsl bash -c ${JSON.stringify('tmux command')}

   Files Updated:
   ✅ conductor-spawn.js (7 functions, 30+ tmux calls)

   Functions Fixed:
   - getNextSessionNumber()
   - sessionExists()
   - spawnOnWSL() [all 3 commands]
   - spawnOnMac() [SSH + tmux]
   - killSession()
   - attachSession()
   - listSessions()

2. Port 3777 Conflict ✅
   Problem: EADDRINUSE port already in use
   Solution: Killed existing process (PID 32536)
   Status: Port now available

TROUBLESHOOTING
═══════════════════════════════════════════════════════════════════════════════

Q: Nothing happens when I double-click start-all.bat
A: Open command prompt and run: cd F:\bounty-board && start-all.bat

Q: Port 3777 already in use
A: netstat -ano | findstr :3777
   taskkill /PID <PID> /F
   Then try again

Q: tmux command not found
A: This should be fixed now. If you still get the error:
   - Verify WSL is installed: wsl --list
   - Try: wsl tmux --version

Q: Agents won't spawn
A: Check the server is running in another terminal
   Look for: "Server online at http://localhost:3777"

Q: Can't see agents working
A: Attach to tmux session: tmux attach-session -t opus-agent-1

Q: Can't complete work / agents unresponsive
A: Kill all and restart:
   - Close all terminals
   - Run: start-all.bat again
