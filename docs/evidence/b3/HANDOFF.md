# b3 / R2 Hub: reply box and Done button on every Needs-you item

## What landed
- **`POST /api/reply`** (`hub/server.js` `reply()`): JSON `{port, bounty_id, text, unblock}`. 403 unless `X-Hub-Request: 1` *and* `Content-Type: application/json` (checked before the body is parsed); malformed JSON is a JSON 400. Only a port in the registry is accepted (404 otherwise, nothing is sent). The hub forwards to `<board>/api/bounties/:id/human-notes` with `X-Board-Request: 1` and `{text, from: human_name, unblock}`, timeout `reply_timeout_ms` (5000). An empty box with unblock sends `"Done"` (server side too). The board's status and body pass through, plus `saved`, `delivered`, `text`, `unblock`. A board that does not answer is a 502. A 409 (unblock on a non-blocked bounty) counts as saved because the board stored the note. After a save the `/api/hub` cache is dropped, so the next refresh shows the new state.
- **`on_reply` hook**: hub config argv array (a plain string is ignored: no shell, ever). It runs with `execFile`, and placeholders are filled in one pass per argument (`fillArgv`), so a `{id}` typed in the text stays literal. Placeholders: `{board}`, `{project}` (the bounty's `project_id` from `GET /api/bounties/:id`, else the board's default), `{port}`, `{id}`, `{title}`, `{text}`, `{unblock}`, `{orchestrator}`. The hook runs only after the board stored the note, and is killed at `hook_timeout_ms` (15000). A non-zero exit, a timeout or a missing binary gives `delivered:false` with `delivery_error`; the reply stays 2xx. No hook gives `delivered:null` (save only).
- **`{orchestrator}`**: `lib/registry.js` `entryFor` copies `board.json` `orchestrator` into the registry entry (null when unset). Added to `config/board.example.json`.
- **`human_name`**: hub config, default `"human"`. `config/hub.example.json` shows `human_name`, a generic `on_reply`, and both timeouts.
- **Page** (`hub/public/hub.js`, `hub.css`): every Needs you item, on All and under "Waiting on you" in the project tab, has a text box, **Send** (submit; Enter in the box sends) and **Done, unblock it**. State per bounty (`port-id`: draft, sending, sent, error) lives outside the DOM, so it survives the 30 s refresh and is mirrored in both tabs. The refresh does not repaint while a reply box with text in it has focus, or while a send is in flight. While sending, the box and buttons are disabled. On success the item shows "You: <text> · <time>", plus "delivered", or "saved on the board, not delivered live", or the 409 warning. On unblock the form hides ("unblocked, leaves Needs you on the next refresh") and the page refreshes after 2.5 s. On failure the inline error reads "Not sent: <reason>. Your text is kept; try again.", the text stays, and focus returns to the box. An empty Send asks for text and sends nothing. On desktop the title and reason sit beside the box, so b1's "every card within 900 px" check still holds with 5 boxes and web fonts. At 480 px and below it stacks, with 44 px touch targets.
- README "One page for every project": replies, the `/api/reply` contract, `on_reply` with its placeholders and timeouts, `human_name`, and `orchestrator`.

## Tests (`npm ci --silent && npm test`: 47 pass, 0 fail, 0 skipped)
- `test/hub.reply.test.js` (node:test, fake boards on ephemeral ports; `test/hub-fixtures.js` fake board now implements the bounty #2 contract: 403 without `X-Board-Request`, 400 empty, 404 unknown, 409 with note stored, unblock sets `ready`):

  - header/content-type 403 (4 variants, nothing reaches the board), bad JSON 400, empty text 400, unregistered port 404, forwarding (header, `from: Robin`, trimmed text), Done with empty text sends `"Done"` + unblock and `/api/hub` no longer lists it, 409 passthrough as saved, 404 passthrough, dead board 502, no hook gives `delivered:null`.
  - hook: every placeholder in argv, with text `it's "done"; rm -rf $HOME $(id) \`x\` {id} | cat` arriving as one verbatim argument. Empty `{orchestrator}` and the `{project}` fallback. No hook run when the board write fails. Exit 3 gives `delivered:false` with "exit code 3: relay said no". A hanging hook is killed at 500 ms and the reply still succeeds. A missing binary is "not found". Every reply was stored.

A hook failure shows "saved on the board, not delivered live". Empty Send is refused. Tab goes box → Send → Done, and Enter on Done sends "Done" with unblock and hides the form; the item leaves Needs you on the refresh and after a reload. At 390 px: no sideways scroll, every input and button on screen and ≥ 40 px tall, tap Send works.
